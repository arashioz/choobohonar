# مدل مدیریت محصول و متریال

این سند قرارداد فعلی پنل ادمین برای داده‌های محصول و متریال را توضیح می‌دهد. هدف، جلوگیری از تبدیل فرم‌ها به مجموعه‌ای از فیلدهای متنی نامنسجم است.

## محصول

هر محصول چهار لایه داده دارد:

1. **هویت و محتوا**: عنوان، اسلاگ، خلاصه، توضیحات کامل، محتوای تفصیلی، تگ‌ها و SEO.
2. **طبقه‌بندی و ارتباطات**: چند دسته‌بندی، چند متریال، چند رنگ/پرداخت، ارجاع مستقیم به رکوردهای کتابخانه متریال و چند کالکشن.
3. **فروش و موجودی**: SKU پایه، قیمت، قیمت قبل از تخفیف، موجودی، حد هشدار، وضعیت سفارش، زمان تحویل و گارانتی.
4. **ساخت و گونه‌ها**: ابعاد، وزن، جدول مشخصات و چند گونه مستقل. هر گونه نام، SKU، قیمت، موجودی و چند ویژگی دارد.

قیمت و موجودی پایه برای محصول بدون گونه استفاده می‌شوند. در صورت وجود گونه، SKU، قیمت و موجودی هر گونه بر مقدار پایه اولویت دارد.

## متریال

هر متریال شامل این لایه‌هاست:

1. **هویت**: عنوان، کد، توضیحات، تصاویر، تگ‌ها و SEO.
2. **طبقه‌بندی چندمقداری**: انواع متریال، رنگ‌ها، پرداخت‌ها و کاربردهای پیشنهادی.
3. **تامین**: چند تامین‌کننده، واحد اندازه‌گیری، قیمت واحد، موجودی، حداقل موجودی و زمان تامین.
4. **فنی**: ویژگی‌های کلید/مقدار، گواهی‌ها و دستور نگهداری.

محصول‌ها متریال را با شناسه رکورد (`materialRefs`) نگه می‌دارند. متن آزاد `materials` فقط برای توضیح ترکیب ساخت یا مواردی است که هنوز در کتابخانه ثبت نشده‌اند.

## رسانه

- هر رکورد چند تصویر یا ویدئو می‌پذیرد.
- فایل‌ها می‌توانند هم‌زمان آپلود شوند.
- ترتیب آرایه، ترتیب گالری است.
- اولین فایل، تصویر اصلی رکورد است.
- رابط کاربری امکان جابه‌جایی و حذف هر مورد را دارد.

## وضعیت انتشار

- `draft`: در حال تکمیل و خارج از API عمومی.
- `published`: قابل دریافت از API عمومی CMS.
- `archived`: نگهداری‌شده ولی خارج از نمایش عمومی.

## ادامه پیشنهادی

برای اتصال کامل فروشگاه، API عمومی باید منبع اصلی صفحات محصول و متریال روی سایت شود. پس از آن، موجودی و قیمت نیز باید از همین مدل خوانده شوند و داده‌های استاتیک فعلی فقط برای مهاجرت یا fallback باقی بمانند.
